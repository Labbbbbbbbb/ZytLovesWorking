这是一个非常经典的双系统引导问题。别担心，**你的 Ubuntu 系统文件大概率还在**（只要没格式化 Ubuntu 所在的分区），只是引导入口（GRUB）被 Windows 重装时覆盖/删除了。

## 🔍 问题原因
- Windows 11 和 Ubuntu 双系统通常共用 **EFI 系统分区（ESP）** 存储引导文件
- 重装 Windows 时，安装程序会**重写 EFI 分区**，将 Windows Boot Manager 设为默认启动项，导致 GRUB 菜单消失
- 开机直接进 Windows，Ubuntu"不见了"，但数据分区通常完好

---

## ✅ 解决方案：使用 Ubuntu Live USB 修复 GRUB（推荐）

### 📦 准备工作
1. 一个 Ubuntu 22.04 安装 U 盘（和你原来系统版本一致最好）
2. 备份重要数据（以防操作失误）

### 🔧 修复步骤

#### 方法一：使用 Boot-Repair 工具（最简单，强烈推荐）

1. **用 Ubuntu 安装 U 盘启动** → 选择「Try Ubuntu without installing」
2. **连接网络**（WiFi 或有线）
3. 打开终端，依次执行：
   ```bash
   # 添加 Boot-Repair 仓库
   sudo add-apt-repository ppa:yannubuntu/boot-repair
   sudo apt update
   
   # 安装并启动 Boot-Repair
   sudo apt install boot-repair
   boot-repair
   ```
4. 在弹出的窗口中点击 **「Recommended repair」**（推荐修复）
5. 按提示操作（可能需要复制几条命令到终端执行）
6. 修复完成后重启，拔掉 U 盘，应该就能看到 GRUB 菜单了

#### 方法二：手动 chroot 修复（进阶，适合熟悉命令行的用户）

如果 Boot-Repair 失败，可手动操作：

```bash
# 1. 确认分区（假设 /dev/nvme0n1p5 是 Ubuntu 根分区，/dev/nvme0n1p1 是 EFI 分区）
lsblk -f

# 2. 挂载 Ubuntu 根分区
sudo mount /dev/nvme0n1p5 /mnt

# 3. 挂载 EFI 分区（ESP）
sudo mount /dev/nvme0n1p1 /mnt/boot/efi

# 4. 挂载必要系统目录
for i in /dev /dev/pts /proc /sys /run; do sudo mount -B $i /mnt$i; done

# 5. 进入 chroot 环境
sudo chroot /mnt

# 6. 重新安装 GRUB 到 EFI 分区
grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=Ubuntu --recheck

# 7. 更新 GRUB 配置
update-grub

# 8. 退出并重启
exit
sudo reboot
```

> ⚠️ 注意：`/dev/nvme0n1pX` 需替换为你实际的分区号，用 `lsblk -f` 或 `sudo fdisk -l` 确认：
> - Ubuntu 根分区：文件系统类型为 `ext4`
> - EFI 分区：类型为 `vfat`，大小约 100-500MB

## 💡 额外建议（避免下次再出问题）

1. **BIOS/UEFI 启动顺序**：修复后如果还是直接进 Windows，开机按 F2/F12/Del 进入 BIOS，将「Ubuntu」设为第一启动项
2. **Windows 快速启动**：在 Windows 中关闭「快速启动」（控制面板 → 电源选项），避免它锁定 EFI 分区
3. **备份 EFI 分区**：未来可定期备份 EFI 分区内容，方便恢复
4. **考虑独立 EFI 分区**：高级用户可为 Ubuntu 单独分配一个小 EFI 分区，降低互相影响风险

然后因为前后两次(第一次安装和重装win之后的修复)efi分区的UUID不同，进入ubuntu之后进入了emergency mode，修改了UUID然后强制重启才解决

UUID（Universally Unique Identifier）是**每个分区的唯一身份证**，不同分区的 UUID 不可能相同，也不应该相同。

## 🔍 为什么 UUID 必须不同？



| 分区         | 挂载点      | 文件系统   | UUID 特点                                         |
| ------------ | ----------- | ---------- | ------------------------------------------------- |
| **根分区**   | `/`         | ext4       | 长格式，如 `760413a4-7b4d-4912-b251-de7b27196ac1` |
| **EFI 分区** | `/boot/efi` | vfat/FAT32 | 短格式，如 `D661-BC1E`                            |

- ✅ **每个分区格式化时会生成独立 UUID**
- ✅ **fstab 通过 UUID 精准识别"哪个分区挂载到哪里"**
- ❌ 如果两个挂载点写同一个 UUID，系统会混乱，导致启动失败

## 🎯 **找到问题了！**

#### 1. 查看所有分区的实际 UUID
sudo blkid

#### 2. 对比 fstab 中的配置
cat /etc/fstab

对比 `fstab` 和 `blkid` 的输出：

### ✅ **根分区 UUID - 正确**
- fstab: `760413a4-7b4d-4912-b251-de7b27196ac1`
- 实际: `760413a4-7b4d-4912-b251-de7b27196ac1`
- **匹配！**

### ❌ **EFI 分区 UUID - 错误！**
- fstab 中: `D661-BC1E`
- 实际: `026F-25D1`
- **不匹配！** ← 这就是导致 emergency mode 的原因

---

## 🔧 **立即修复：**

```bash
# 编辑 fstab 文件
sudo nano /etc/fstab   #vi也可以
```

**找到这一行：**
```
UUID=D661-BC1E  /boot/efi  vfat  umask=0077  0  1
```

**改成：**
```
UUID=026F-25D1  /boot/efi  vfat  umask=0077  0  1
```

**保存退出：**
- 按 `Ctrl + O` → 回车（保存）
- 按 `Ctrl + X`（退出）

---

## ✅ **验证修复：**

```bash
# 再次检查 fstab
cat /etc/fstab

# 重启系统
sudo reboot
```

重启后应该就能正常进入 Ubuntu 了！🎉

---

## 📝 **原因分析：**
重装 Windows 时，EFI 分区被重新格式化，生成了新的 UUID (`026F-25D1`)，但 Ubuntu 的 fstab 还保留着旧的 UUID (`D661-BC1E`)，导致系统启动时找不到 EFI 分区。
